## 3. One Fix Remaining Before Launch

**File:** `fbar-automator/d2c/src/app/api/filing/form114a/route.ts`

**Problem:** The route has no try/catch. If `prisma.filingYear.findFirst` or `downloadFile` (S3) throws, Next.js returns an HTML 500 page instead of a JSON error. Every other API route in the codebase handles this pattern.

**Fix (5 minutes):**
```typescript
export async function GET(req: NextRequest) {
  try {
    const session = await auth();
    if (!session?.user?.id) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
    }
    // ... rest of existing code ...
  } catch (error) {
    logger.error("form114a download failed", { error });
    return NextResponse.json({ error: "Download failed" }, { status: 500 });
  }
}
```

**Current state of the file (35 lines, no try/catch):**
```
src/app/api/filing/form114a/route.ts
  Line 17: const filing = await prisma.filingYear.findFirst(...)  ← unguarded DB call
  Line 25: const buffer = await downloadFile(filing.form114aUrl)  ← unguarded S3 call
```

This is the only API route without error handling. It should be fixed before launch.
